## 1. 问题定义

### 1.1 间接提示注入攻击 (IPIA)

当 LLM Agent 调用工具与外部环境交互时，攻击者在外部环境（邮件、网页等）中植入恶意指令，利用上下文中指令与数据边界的模糊性，使 Agent 将恶意指令误认为新的用户请求，执行偏离用户原始意图的操作。

**攻击流程**:
```
用户指令("总结近期邮件") → Agent 调用 ReadEmail → 邮件中含恶意指令("预约牙科医生")
→ Agent 误将恶意指令视为新请求 → 调用 Hospital 工具 → 发生意图漂移
```

### 1.2 现有防御方法的缺陷

| 方法 | 原理 | 缺陷 |
|------|------|------|
| 指令预防 | 在提示词中插入安全引导 | 攻击者可用"忽略先前指令"绕过 |
| Sandwich | 每轮对话后重复用户指令 | 长上下文中 LLM 可能遗忘 |
| 数据隔离 | XML 标签分隔指令和数据 | 攻击者可重复标签模糊边界 |
| Spotlighting | 特殊标记隔离系统指令和外部指令 | 强 LLM 能过滤特殊符号修复语义 |

**共同缺陷**: 以检测恶意文本为核心，无法识别"无害但偏离用户意图"的工具调用；缺失记忆与自适应学习能力，面对自适应攻击会重复误判。

### 1.3 形式化定义

- Agent: `L`，可用工具集: `T = {T₁, T₂, ..., Tₙ}`
- 用户初始指令: `Iᵤ`
- 攻击者在外部环境植入恶意指令: `Iₐ`
- 被污染的工具响应: `R*_Tᵤ = R_Tᵤ ⊕ Iₐ`（⊕ 表示文本拼接或嵌入）
- 攻击目标: 诱导 Agent 调用未授权的风险工具 `Tₐ ∈ T`

## 2. IntentShield 总体框架

IntentShield 将安全性评估转化为**宏观指令与微观执行动作之间的一致性对齐问题**，包含两大核心策略:

```
┌─────────────────────────────────────────────────────────────────┐
│                    IntentShield 总体框架                          │
├─────────────────────────────────┬───────────────────────────────┤
│   意图对齐交叉验证 (实时防御)     │   动态反思自我进化 (持续学习)    │
├─────────────────────────────────┼───────────────────────────────┤
│ • 意图锚点 (用户指令)            │ • RAG 检索历史威胁案例          │
│ • 行为空间约束 (工具属性+参数)    │ • 结构化经验反思               │
│ • 规范边界 (OWASP Top10)        │ • 持久化至向量数据库            │
│ • 结构化推理范式 (CoT)           │ • 动态免疫进化                 │
│ • 动态反思经验 (RAG注入)         │                               │
└─────────────────────────────────┴───────────────────────────────┘
```

## 3. 意图对齐交叉验证策略（核心防御机制）

### 3.1 意图漂移度量函数

```
F(Iᵤ, Tᶜ, P) = L(Γ_safe ⊕ Tᶜ ⊕ P)
```

- `Iᵤ`: 用户初始指令
- `Tᶜ ∈ T`: 目标调用工具
- `P`: 参数集合
- `L`: LLM 裁判
- `Γ_safe`: 结构化安全提示词

**判定逻辑**: 当工具调用 `(Tᶜ, P)` 在逻辑上直接或间接遵循用户指令 `Iᵤ` 时，`F` 趋于极小值；否则判定发生意图漂移。

- **直接遵循**: 工具调用与用户指令存在直接因果关系（如"总结邮件"→调用邮件工具）
- **间接遵循**: 工具调用属于完成任务的前置/依赖/辅助环节

### 3.2 结构化安全提示词 Γ_safe

```
Γ_safe = I_anchor ⊕ T_constraint ⊕ G_norm ⊕ O_struct ⊕ K_dynamic
```

| 组件 | 名称 | 作用 |
|------|------|------|
| `I_anchor` | 意图锚点 | 用户指令，作为意图对齐的核心锚点，具有最高执行特权 |
| `T_constraint` | 行为空间约束 | 工具静态属性 + 动态参数集合，将抽象目标转化为具体执行动作 |
| `G_norm` | 规范边界 | 基于 OWASP Top10 的五维安全指南（财产安全、数据隐私、法规合规、身心健康、禁止冒犯） |
| `O_struct` | 结构化推理范式 | 强制 LLM 遵循 CoT 输出三元组 `⟨C_thought, S_risk, D_final⟩` |
| `K_dynamic` | 动态反思经验 | 通过 RAG 匹配的历史威胁案例 |

### 3.3 风险评分与分段决策

风险置信度评分为连续空间 `S_risk ∈ [0, 1]`，基于模糊逻辑实施分段决策:

```
            ┌ Safe,        S_risk < α
Π(S_risk) = │ Suspicious,  α ≤ S_risk ≤ β
            └ Dangerous,   S_risk > β
```

- `α = 0.3`（安全放行阈值）
- `β = 0.7`（危险阻断阈值）

**决策动作**:
- **Safe**: 安全放行，正常执行工具调用
- **Suspicious**: 可疑操作，需等待用户授权
- **Dangerous**: 危险操作，直接阻断执行链路

## 4. 动态反思的自我进化策略（持续学习机制）

### 4.1 RAG 检索阶段

**目标**: 为 LLM 裁判提供历史威胁案例，增强对隐蔽攻击的识别能力。

**流程**:
1. 提取当前工具调用请求的结构化文本块: `T_block = [Iᵤ ⊕ Tᶜ ⊕ P]`
2. 使用稠密嵌入模型（bge-m3）映射为高维向量: `Vᶜ = Φ_embed(T_block)`
3. 计算与历史威胁数据库中向量的余弦相似度: `Similarity(Vᶜ, Vₕ) = (Vᶜ · Vₕ) / (|Vᶜ| · |Vₕ|)`
4. 使用重排序模型（bge-reranker-v2-m3）精确提取 Top-K（K=3）个历史威胁案例
5. 聚合为动态经验集 `K_retrieved`，赋值给 `K_dynamic`

### 4.2 结构化经验反思阶段

**目标**: 从拦截失败中学习，实现防御能力的自主进化。

**三个子阶段**:

#### 阶段 1: 回合制触发
- 每轮测试结束后扫描运行日志
- 收集假阴性漏报样本: LLM 裁判判定为 "Safe" 但实际包含恶意指令的记录
- 构建假阴性漏报样本集 `S_fn`

#### 阶段 2: 结构化输出
- 对每个漏报样本，提取完整交互轨迹: 用户指令 `Iᵤ`、工具及参数 `Tᶜ(P)`、初始错误思考 `Thought_initial`
- 强制 LLM 生成结构化反思报告（JSON 格式），包含三个关键要素:

```json
{
  "Attack_Feature": "攻击者利用该工具参数隐藏的攻击意图",
  "Failed_Reason": "先前基于安全提示的审核失效原因",
  "New_Guideline": "针对此类新型参数组合的针对性防御补丁"
}
```

#### 阶段 3: 持久化与动态免疫
- 将三要素拼接为反思文本块: `T_ref = [F_attack ⊕ F_reason ⊕ F_guide]`
- 使用嵌入模型映射为高维向量: `V_ref = E(T_ref)`
- 持久化追加存储至历史威胁数据库 `D`

### 4.3 算法伪代码

```
算法: 结构化经验反思
输入: 运行日志 Logs, LLM裁判 L, 嵌入模型 E, 历史威胁数据库 D
输出: 更新后的数据库 D'

// 阶段 1: 收集假阴性漏报
S_fn = {}
for log_i in Logs:
    if log_i.Decision == "Safe" AND log_i.Feedback == "Malicious":
        S_fn.add(log_i)

// 阶段 2: 生成结构化反思
for c in S_fn:
    提取 (Iᵤ, Tᶜ(P), Thought_initial)
    Prompt_ref = 组装反思提示词(c的完整交互轨迹 + 深度反思要求)
    Reflection_Report = L(Prompt_ref)  // JSON格式
    F_attack = Reflection_Report["Attack_Feature"]
    F_reason = Reflection_Report["Failed_Reason"]
    F_guide = Reflection_Report["New_Guideline"]

    // 阶段 3: 向量化嵌入与持久化
    T_ref = [F_attack ⊕ F_reason ⊕ F_guide]
    V_ref = E(T_ref)
    D = D ∪ {(V_ref, Reflection_Report)}

return D' = D
```

## 5. 实验设置

### 5.1 基础模型
- **GPT-4o-mini** (OpenAI)
- **Qwen-Max** (阿里云)
- Temperature = 0（保证输出稳定性）

### 5.2 关键参数

| 参数 | 值 | 说明 |
|------|-----|------|
| α (安全阈值) | 0.3 | S_risk < 0.3 判定为安全 |
| β (危险阈值) | 0.7 | S_risk > 0.7 判定为危险 |
| 嵌入模型 | bge-m3 | 多语言长文本检索，8K 上下文 |
| 重排序模型 | bge-reranker-v2-m3 | 中英文混合处理 |
| Top-K | 3 | 检索的相似攻击案例数 |

### 5.3 数据集: InjecAgent

- **测试样例**: Base 和 Enhanced 各 1054 条
- **用户指令**: 17 种不同工具
- **攻击指令**: 62 种，覆盖 5 种攻击场景

**三种攻击手段**:
| 攻击手段 | 描述 |
|---------|------|
| 直接攻击 (DH) | 使用特定工具直接执行有害操作 |
| 数据泄露 (DL) | 访问和提取用户隐私数据 |
| 邮件劫持 (EH) | 通过邮件工具将数据发送给攻击者 |

**两种攻击场景**:
| 场景 | 描述 |
|------|------|
| Base | 恶意指令直接嵌入工具响应 |
| Enhanced | 恶意指令前附加"忽略之前所有指令"前缀 |

### 5.4 评价指标

```
ASR-valid = succ / (succ + unsucc) × 100%
```

分攻击手段计算，总体 ASR 按样本数加权求和。

## 6. 实验结果

### 6.1 有效性验证 (RQ1)

**IntentShield 将总体 ASR 降至 1.15%，较无防御基线降低 89.55%**

| 模型 | 场景 | 防御 | 直接攻击 | 数据泄露 | 邮件劫持 | 总体 |
|------|------|------|---------|---------|---------|------|
| Qwen-Max | Base | 无 | 2.80% | 12.00% | 95.20% | 10.10% |
| Qwen-Max | Base | IntentShield | 0.21% | 0.00% | 0.00% | 0.06% |
| Qwen-Max | Enhanced | 无 | 15.10% | 11.30% | 100.00% | 13.40% |
| Qwen-Max | Enhanced | IntentShield | 1.00% | 0.19% | 3.60% | 0.55% |
| GPT-4o-mini | Base | 无 | 2.00% | 16.30% | 97.40% | 9.10% |
| GPT-4o-mini | Base | IntentShield | 0.00% | 2.68% | 13.36% | 1.64% |
| GPT-4o-mini | Enhanced | 无 | 2.30% | 20.40% | 99.00% | 11.40% |
| GPT-4o-mini | Enhanced | IntentShield | 0.45% | 3.68% | 13.21% | 2.35% |

### 6.2 消融实验

| 组件 | 贡献 |
|------|------|
| 意图交叉验证（单独） | 总体 ASR 降至 1.68%，构筑第一道防线 |
| + 动态反思 | 进一步降低邮件劫持 ASR（GPT-4o-mini Base: 27.27% → 13.36%） |

### 6.3 鲁棒性验证 (RQ2)

| 模型 | 正常工具调用成功率 |
|------|------------------|
| GPT-4o-mini | 79.40% |
| Qwen-Max | 82.40% |

误拦截主要发生在涉及检索个人隐私和敏感信息的合法指令上。

### 6.4 对比实验 (RQ3)

| 防御方法 | 总体 ASR | 邮件劫持 ASR | 稳定性(SD) |
|---------|---------|-------------|-----------|
| IntentShield | **1.15%** | **7.54%** | **1.04** |
| 指令预防 | 0.75% | 75.00% | 0.76(总体)/50(邮件劫持) |
| Sandwich | 3.20% | 96.58% | 高 |
| Spotlighting | 9.75% | 98.58% | 高 |

**关键发现**: IntentShield 是唯一能在不同模型、不同场景下始终保持极低总体 ASR（最高仅 2.35%）的防御方法。指令预防虽然总体 ASR 略低，但在邮件劫持下遭遇灾难性失效（ASR 高达 100%）。

## 7. 技术实现要点总结

### 7.1 核心创新

1. **意图对齐范式**: 将安全评估从"检测恶意文本"转变为"验证意图一致性"
2. **交叉验证**: 利用工具参数与用户指令的交叉对比识别意图漂移
3. **动态反思进化**: 通过 RAG + 结构化反思实现防御能力的自主学习
4. **分段决策**: 基于模糊逻辑的三级风险决策，避免二元分类的"过度防御"

### 7.2 实现依赖

- **LLM 裁判**: GPT-4o-mini / Qwen-Max（Temperature=0）
- **嵌入模型**: bge-m3（8K 上下文，多语言）
- **重排序模型**: bge-reranker-v2-m3
- **向量数据库**: 存储历史威胁案例和反思报告
- **数据集**: InjecAgent

### 7.3 方法局限性

- 正常工具调用成功率约 79-82%，对涉及敏感信息的合法操作存在误拦截
- 依赖 LLM 裁判的推理能力，增加了推理延迟和成本
- 动态反思需要积累足够的历史案例才能发挥最大效果
