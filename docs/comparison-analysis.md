# AgentDojo vs InjecAgent 对比分析

## 项目定位对比

| 维度 | AgentDojo | InjecAgent |
|------|-----------|------------|
| 开发者 | ETH Zurich + Invariant Labs | 学术研究团队 |
| 核心目标 | 评估攻击与防御的完整框架 | 评估 Agent 对间接注入的脆弱性 |
| 侧重点 | 攻防双向 (攻击 + 防御) | 攻击单向 (仅评估脆弱性) |
| 架构风格 | 工程化框架 (可扩展、可组合) | 研究型基准 (固定数据集) |
| 代码规模 | 大型 (多模块、多版本) | 中型 (聚焦评估脚本) |

## 攻击方法对比

| 维度 | AgentDojo | InjecAgent |
|------|-----------|------------|
| 攻击类型 | 7+ 种攻击策略 (从简单到复杂) | 2 种攻击类型 (DH + DS) |
| 注入方式 | 动态注入向量 (运行时确定可见点) | 静态模板注入 (预定义注入位置) |
| 攻击复杂度 | 分层递进 (Direct → Important Instructions → Tool Knowledge) | 二级设置 (Base → Enhanced) |
| DoS 攻击 | 支持 (多种变体) | 不支持 |
| 攻击目标 | 执行特定函数调用 | 调用攻击者工具 |

## 评估方法对比

| 维度 | AgentDojo | InjecAgent |
|------|-----------|------------|
| 评估维度 | Utility + Security 双维 | ASR (攻击成功率) 单维 |
| Agent 类型 | 管道式 (可组合组件) | ReAct + Function Calling |
| 任务域 | 4 个 (Workspace, Banking, Travel, Slack) | 17 种用户工具场景 |
| 测试规模 | 动态生成 (用户任务 × 注入任务) | 固定 1,054 个用例 |
| 防御评估 | 内置 4 种防御机制 | 无内置防御 |

## 技术实现对比

| 维度 | AgentDojo | InjecAgent |
|------|-----------|------------|
| 语言 | Python (类型注解完善) | Python |
| 依赖管理 | pyproject.toml + uv | requirements.txt |
| 数据格式 | YAML 环境 + Python 类 | JSONL/JSON 数据文件 |
| 可扩展性 | 高 (注册系统、插件式) | 低 (固定结构) |
| 版本管理 | 多版本基准 (v1.0 ~ v1.2.2) | 单版本 |
| 缓存机制 | LRU 缓存 + ground truth 复用 | 文件级缓存 (--use_cache) |

## 互补关系

两个项目在 prompt injection 防御研究中形成互补:

1. **AgentDojo 的优势**:
   - 完整的攻防评估框架
   - 内置防御机制可直接对比
   - 工程化设计，易于扩展新攻击/防御
   - 动态注入点检测更贴近真实场景
   - 双维评估避免"安全但无用"的防御

2. **InjecAgent 的优势**:
   - 更广泛的工具覆盖 (62 种攻击者工具)
   - 两阶段数据窃取攻击更贴近真实威胁
   - 支持更多开源模型 (100+)
   - 固定数据集便于横向对比
   - 攻击分类更细致 (物理/金融/数据等)

## 对防御研究的启示

### 从 AgentDojo 学到的

1. **防御必须保持功能性**: Utility + Security 双维评估是关键
2. **分层防御**: 工具过滤 + PI 检测 + 提示强化可组合使用
3. **动态检测**: 基于 canary 值的注入点检测比静态模板更可靠
4. **攻击多样性**: 防御需要对抗从简单到复杂的多种攻击策略

### 从 InjecAgent 学到的

1. **间接注入是主要威胁**: 攻击通过工具返回内容而非直接用户输入
2. **多阶段攻击更危险**: 数据窃取需要两步操作，更难检测
3. **工具权限是关键**: 62 种攻击者工具说明权限控制的重要性
4. **增强提示显著提升攻击成功率**: Base vs Enhanced 设置的差异

### 综合防御策略建议

1. **输入层**: 工具输出内容的 PI 检测 (AgentDojo 的 transformers_pi_detector)
2. **权限层**: 限制 Agent 可调用的工具范围 (AgentDojo 的 tool_filter)
3. **提示层**: 强化系统提示，明确区分指令与数据 (spotlighting)
4. **行为层**: 检测异常工具调用模式 (InjecAgent 的多阶段攻击检测)
5. **确认层**: 高风险操作需用户确认 (结合两者的工具分类)
